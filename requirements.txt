# requirements.txt - Python Dependencies for MCP Sum Server
# =====================================================
#
# Why do we need a separate requirements.txt file?
# ================================================
# 
# 1. DEPENDENCY MANAGEMENT:
#    - Python projects often depend on external libraries (packages)
#    - requirements.txt is the standard way to specify these dependencies
#    - It ensures everyone running this code has the same library versions
#    - Without this file, users would get "ModuleNotFoundError" when trying to run the server
#
# 2. REPRODUCIBLE ENVIRONMENTS:
#    - Different versions of libraries can behave differently
#    - By specifying exact versions, we ensure the code works the same everywhere
#    - This prevents "it works on my machine" problems
#    - Critical for production deployments and team collaboration
#
# 3. EASY INSTALLATION:
#    - Users can install all dependencies with one command: pip install -r requirements.txt
#    - No need to manually install each package one by one
#    - Reduces setup friction for new users
#
# 4. VIRTUAL ENVIRONMENT SUPPORT:
#    - Works seamlessly with Python virtual environments
#    - Helps isolate this project's dependencies from other Python projects
#    - Prevents dependency conflicts between different projects
#
# 5. DEPLOYMENT AUTOMATION:
#    - CI/CD systems can automatically install dependencies
#    - Docker containers can use this file to set up the environment
#    - Cloud platforms often automatically detect and install from requirements.txt

# Core MCP (Model Context Protocol) library
# =========================================
# This is the main library that provides all MCP server functionality
# Version 1.0.0 is specified to ensure compatibility and reproducibility
# Without this, our server wouldn't be able to:
# - Handle MCP protocol communication
# - Register tools and handle tool calls
# - Communicate with MCP clients (like AI assistants)
mcp==1.0.0

# Why do we specify exact versions (==) instead of minimum versions (>=)?
# ======================================================================
# 
# PROS of exact versions (==):
# - Guaranteed reproducibility - same behavior everywhere
# - No surprises from automatic updates
# - Easier to debug issues since everyone has same versions
# - Better for production stability
#
# CONS of exact versions (==):
# - Don't automatically get bug fixes and security updates
# - May conflict with other projects that need different versions
# - Require manual updates to get new features
#
# ALTERNATIVE APPROACHES:
# - Compatible versions: mcp~=1.0.0 (allows 1.0.1, 1.0.2, but not 1.1.0)
# - Minimum versions: mcp>=1.0.0 (allows any version 1.0.0 or higher)
# - Version ranges: mcp>=1.0.0,<2.0.0 (allows 1.x but not 2.x)
#
# For this simple example, we use exact versions for maximum predictability

#    python -m venv mcp_env
